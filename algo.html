Agent 1 Sheet Intelligence & Header Discovery

1.1 Range Unmerging & Forward Fill Algorithm Time: O(M × S) | Space: O(R × C)

Brokers frequently merge category cells across columns (e.g., merging columns D–F as "Values (USD)"). Standard pandas parsers fill only the top-left cell and leave subsequent cells as NaN.

  1. Load workbook using openpyxl.load_workbook(path, data_only=True) to evaluate stored formulas.
  2. Iterate over ws.merged_cells.ranges. For each cell range $(r_1, c_1) \dots (r_2, c_2)$, extract top-left value $V = \text{cell}(r_1, c_1)$.
  3. Unmerge the range using ws.unmerge_cells(range_string).
  4. Propagate $V$ into all $(r, c) \in [r_1, r_2] \times [c_1, c_2]$.
  5. Convert worksheet values into a clean pd.DataFrame.

1.2 Header Row Scoring Algorithm Time: O(K × C) | Space: O(C)

The algorithm scans the first $K = 30$ rows of the unmerged worksheet to detect the true column header index, ignoring cover banners and corporate logos.

Candidate Header Row Score Formula
Scoreheader(i) = 0.40 × HeaderMatch(i) + 0.20 × TextRatio(i) + 0.20 × FillRatio(i) + 0.20 × DataBelow(i)
Where for row i:
  • HeaderMatch(i) = fraction of non-null cells matching normalized target field synonyms:
    HeaderMatch(i) = ∑ [norm(cell) ∈ SynonymSet] / max(|non-null|, 1)
  • TextRatio(i) = fraction of non-null cells that are non-numeric strings.
  • FillRatio(i) = ratio of non-null cells to total row width: |non-null| / max(C, 1).
  • DataBelow(i) = fraction of numeric cells in row i+1 (headers are followed by numeric data).

Selection: header_row = argmax0 ≤ i < min(30, N) Scoreheader(i)

1.3 Sheet Classification & Ranking Time: O(S × (K × C + Rsub × C)) | Space: O(S)

To disambiguate multi-tab workbooks (e.g. "Cover Page", "Summary", "Locations SOV", "Pivot"), the agent calculates a composite viability score for each sheet:

Sheet Viability Composite Formula
Scoresheet = 0.35 × Sheader + 0.25 × Ddensity + 0.20 × Ctype + 0.20 × Vrows
Components:
• Sheader = min(1.0, (matches / 17) × 3.0): Synonym match volume.
• Ddensity = non_null_ratio: Global fill rate of the matrix.
• Ctype: Type consistency ratio across columns below header (percentage of columns with >80% pure numeric or >80% pure text).
• Vrows = min(1.0, data_rows_below / 100): Volume factor saturating at 100 rows.
Decision Boundary
• If Scoresheet ≥ 0.45 AND matches ≥ 3 ⇒ PRIMARY SOV SHEET
• Else if Scoresheet ≥ 0.25 OR matches ≥ 1 ⇒ SECONDARY SCHEDULE
• Otherwise ⇒ REJECT (Skip Tab)

For each source column $c$, the agent executes a sequential cascade, stopping at the earliest decisive match or combining signals:

2.2 Unified Confidence Calibration Formula Formula: Wname + Wvalue + Wmethod

Unlike naive string matchers, the final confidence integrates both lexical/semantic match strength and statistical value-profile compatibility:

Multi-Modal Column Confidence Formula
Confidence = Wname × Sname + Wvalue × Vprofile + Wmethod × Amethod
Weight Distribution:
• Wname = 0.45: Lexical/Semantic name similarity score.
• Wvalue = 0.35: Value Profile Fit (VPF) score ($0.0 \dots 1.0$).
• Wmethod = 0.20: Method agreement factor ($1.0$ if memory/exact hit or fuzzy & semantic agree; $0.8$ if single heuristic matches; $0.6$ on heuristic clash).
• Memory Multiplier: If retrieved from approved memory: Confidence ← min(0.99, Confidence × 1.10).

2.3 1:1 Target Uniqueness (Hungarian Conflict Resolution) Time: O(T × K log K) | Space: O(C)

Insurance underwriting schemas forbid multiple source columns from populating the same target field (e.g. if a broker has "Building Value" and "TIV Building", both cannot map to Building Value).

Assignment Heuristic
For each target field $T \in \text{TARGET\_FIELDS}$:
  1. Find all source columns $\{C_1, C_2, \dots, C_k\}$ assigned to $T$.
  2. If $k > 1$: Sort candidates in descending order of calibrated confidence.
  3. Assign $T$ to $C^* = \arg\max_i \text{Confidence}(C_i \to T)$.
  4. Demote all competing columns $C_{j \ne *}$ to UNRESOLVED with confidence = 0.0 and note the demotion reason in the audit trail.

Deep Dive Value Profile Fit (VPF) Scoring Matrix

To prevent absurd false positives (e.g., mapping a column named "State" containing large numbers $50,000,000 to the geographic field State), the profiler analyzes actual cell values against target field expectation profiles.

Heavy penalty if negative values or text ratio > 20%.

Agent 3 Data Quality Rules & Composite Index

3.1 Deterministic Anomaly Detection Time: O(R × F) | Space: O(F)

Agent 3 evaluates 10 strict data quality checks over the mapped dataset:

1. Completeness Checks:

Computes null percentage for each target field. Triggers HIGH severity if null rate >50%, MEDIUM if >20%, LOW if >5%.

2. Monetary Validations:

Detects unparsed currency signs ($, ,) → suggests strip_currency. Detects negative monetary exposures → flags HIGH risk.

3. Temporal & Physical Limits:

Year Built outside [1700, Current Year] → suggests to_year_int. Storey counts < 1 or Building counts < 1 → flags logical error.

4. Standard Codes & Geographic Integrity:

Non-standard sprinkler codes → suggests normalize_sprinkler_code. Full state names → suggests state_to_abbrev. 9-digit or malformed ZIPs → suggests to_zip.

3.2 The SOV Data Quality Index Formula Range: 0.0 – 100.0

The system outputs an underwriting confidence score summarizing the global integrity of the submission:

Aggregated Quality Score Formula
QualityScore = 100 × [ 0.35 × Qmapping + 0.30 × Qcompleteness + 0.35 × Qanomalies ]
Component Breakdown:
• Qmapping = (∑m ∈ mapped Confidence(m)) / 17: Ratio of successfully matched schema dimensions.
• Qcompleteness = (∑f ∈ fields NonNullRate(f)) / (17 × 100): Aggregate matrix fill density.
• Qanomalies = max(0.0, 1.0 - ∑i ∈ issues w(i)): Penalty reduction where:
  – w(High) = 0.15 per critical anomaly (e.g. duplicate IDs, negative values)
  – w(Medium) = 0.05 per format/code issue (e.g. unstripped currency)
  – w(Low) = 0.02 per minor type mismatch

Agent 4 Controlled Transformation Sandbox

4.1 The Zero-Hallucination Mutex Execution Engine Time: O(R × A) | Space: O(R × C)

Agent 4 executes only after human approval. To eliminate generative hallucinations, transformations operate within a sandboxed functional registry: 

# The Transformation Sandbox Execution Pipeline
def apply_approved_transformations(df: pd.DataFrame, approved_recs: List[Recommendation]):
    for rec in approved_recs:
        if rec.status != RecommendationStatus.APPROVED:
            continue
        
        # Security invariant: Refuse unlisted functions
        if rec.operation not in WHITELISTED_OPERATIONS:
            raise SecurityException(f"Illegal operation '{rec.operation}' rejected.")
            
        target_series = df[rec.target_column]
        before_snapshot = target_series.copy()
        
        # Execute pure deterministic vector transformation
        df[rec.target_column] = apply_transformation_to_series(rec.operation, target_series)
        
        # Measure row-level mutation mask & compile audit entry
        diff_mask = (df[rec.target_column] != before_snapshot) & target_series.notna()
        record_audit_log(rec, rows_modified=int(diff_mask.sum()))

4.2 DataFrame Disambiguation & Collision Resolution Time: O(Cdup × R) | Space: O(1)

Real-world SOVs often have duplicated column headers (e.g., 3 separate columns all labeled 2024 - Increase 10%). Slicing df[col] yields a multi-column DataFrame rather than a Series, crashing subsequent operations.

Collision Resolution Algorithm
1. Header Deduplication: During initial extraction, headers are scanned. If header $H$ exists $k$ times, suffix indices $H, H\_1, H\_2, \dots$ are assigned.
2. Series Slicing Disambiguation: If isinstance(df[col], pd.DataFrame) occurs at runtime, the agent evaluates notna().sum() across all candidate column slices, retains the slice with maximum non-null data volume, and drops redundant empty duplicates.
3. Target Renaming Protection: If a source column is renamed to target $T$ while an existing column is already named $T$, the existing column is proactively isolated to _orig_{T}.

Agent 5 Validation & Export Engine

5.1 Pandera Contract Enforcement Time: O(R × 17) | Space: O(1)

Before any file is written to disk, the DataFrame must pass strict validation against the Pandera 17-column specification:

  1. Cardinality Check: len(df.columns) == 17 (Strict equality).
  2. Ordered Key Alignment: Columns must strictly equal:
    ["Reference", "Address", "City", "State", "Zip", "County", "Country", "Building Value", "Contents", "BI", "Occupancy", "Construction", "Storeys", "Number of Buildings", "Year Built", "Fire Sprinklers (Y/N)", "Other"].
  3. Null Padding: Any unmapped canonical column is initialized as an empty series with dtype object (represented as clean Excel blanks).
  4. Pruning: Excess raw columns not approved for inclusion are safely dropped.
  5. Pandera Lazy Validation: DataFrameSchema(columns={col: Column(nullable=True, required=True)}, strict=True, ordered=True).validate(df, lazy=True).
