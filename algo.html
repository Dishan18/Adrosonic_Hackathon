1. End-to-End Algorithmic Data Flow

The system models Statement of Values (SOV) processing as a state machine orchestrated via LangGraph. Each node receives a deep copy of SOVState and writes only its own fields. The graph pauses (checkpointed) before the human review node and resumes into the transformation once the reviewer is done.

Stage Agent Name Primary Operation Data Mutability Deterministic?

Agent 1 Sheet Intelligence & Header Discovery

1.1 Range Unmerging & Fill-Down Algorithm Time: O(M × Rm + R × C) | Space: O(R × C)

Brokers merge cells both vertically (one Loc # spanning several building rows) and horizontally (a "2023 - 2024 Values" banner over D–F, or a footnote merged across B–AB). Only the vertical case carries a value that belongs to every row. Copying a horizontal merge across its columns writes banner or footnote text into unrelated fields; in SOV_B4ID.xlsx this produced Zip "20182" and Year Built 2018 from the note "updates in 2018 to 2019".

  1. Load the workbook once with openpyxl.load_workbook(path, data_only=True) (stored formula results). The parse is cached per (path, modification time) and shared by all agents.
  2. Iterate over ws.merged_cells.ranges. For each range (r1, c1) … (r2, c2), read the top-left value V = cell(r1, c1).
  3. Unmerge the range using ws.unmerge_cells(range_string).
  4. Write V into cell(r, c1) for every r ∈ [r1, r2]: fill down the first column only. Other columns of the range stay empty.
  5. Convert worksheet values into a pd.DataFrame. After the header is applied, blank rows, total rows, note rows (a single non-numeric text cell) and whitespace-only rows are dropped.

1.2 Header Row Scoring Algorithm Time: O(K × C) | Space: O(C)

The algorithm scans the first K = 30 rows of the unmerged worksheet to detect the true column header index, ignoring cover banners and corporate logos.

Candidate Header Row Score Formula
Scoreheader(i) = 0.40 × HeaderMatch(i) + 0.20 × TextRatio(i) + 0.20 × FillRatio(i) + 0.20 × DataBelow(i)
Where for row i:
  • HeaderMatch(i) = fraction of non-null cells matching normalized target field synonyms:
    HeaderMatch(i) = ∑ [norm(cell) ∈ SynonymSet] / max(|non-null|, 1)
  • TextRatio(i) = fraction of non-null cells that are non-numeric strings.
  • FillRatio(i) = ratio of non-null cells to total row width: |non-null| / max(C, 1).
  • DataBelow(i) = fraction of numeric cells in row i+1 (headers are followed by numeric data).

Selection: header_row = argmax0 ≤ i < min(30, N) Scoreheader(i)

1.3 Sheet Classification & Ranking Time: O(S × (K × C + Rsub × C)) | Space: O(S)

To disambiguate multi-tab workbooks (e.g. "Cover Page", "Summary", "Locations SOV", "Pivot"), the agent calculates a composite viability score for each sheet:

Sheet Viability Composite Formula
Scoresheet = 0.35 × Sheader + 0.25 × Ddensity + 0.20 × Ctype + 0.20 × Vrows
Components:
• Sheader = min(1.0, (matches / 17) × 3.0): Synonym match volume.
• Ddensity = non_null_ratio: Global fill rate of the matrix.
• Ctype: Type consistency ratio across columns below header (percentage of columns with >80% pure numeric or >80% pure text).
• Vrows = min(1.0, data_rows_below / 100): Volume factor saturating at 100 rows.
Decision Boundary
• If Scoresheet ≥ 0.45 AND matches ≥ 3 ⇒ PRIMARY SOV SHEET
• Else if Scoresheet ≥ 0.25 OR matches ≥ 1 ⇒ SECONDARY SCHEDULE
• Otherwise ⇒ REJECT (Skip Tab)
Data Sheets (multi-tab merge)
The best-scoring PRIMARY sheet is primary_sheet_name. Every PRIMARY sheet is a data sheet: each is extracted with its own header row and the frames are stacked into one table (columns aligned by header name). For SOV_Q8B3.xlsx this merges 23-24 Values, Deleted Locations and Insured Elsewhere into 990 rows. Hidden sheets are scored like any other.

Agent 2 Schema Mapping & Confidence Calibration

2.1 The Resolution Cascade Worst: O(C × (Ksyn + D + LLM)) | Avg: O(C)

For each source column, memory and exact matches are decisive when the column's values agree. Otherwise up to five fuzzy and five semantic candidate targets are scored together and the best one (confidence ≥ 0.50) is taken. A candidate whose values contradict the field is vetoed at every tier (section 2.2).

Tier Method Algorithm / Mechanism Cost Name Similarity Sname
Tier 0 Vector Memory ChromaDB nearest neighbour over human-approved mappings; hit if similarity (1 − d/2) > 0.85 One Chroma query per header; skipped when the store is empty, cached per header min(stored_conf, 0.99); final confidence × 1.10 (cap 0.99)
Tier 1 Exact Match O(1) hash lookup of the normalized header against the 17 canonical names and 130 synonyms Constant 0.97
Tier 2 Fuzzy Match RapidFuzz token_sort_ratio, cutoff ≥ FUZZY_THRESHOLD × 100 (75); top 5 distinct targets CPU string comparison, cached per header (score / 100) × 0.92
Tier 3 Semantic Vector Cosine similarity with BAAI/bge-small-en-v1.5 (384-d), cutoff ≥ SEMANTIC_THRESHOLD (0.70); top 5 distinct targets CPU embedding, cached per header cosine_sim × 0.90 (average with fuzzy if both find the target)
Tier 4 LLM Gateway Structured JSON decision (Ollama / Groq / Gemini) among fields with value fit > 0.35; only for columns still unresolved; masked sample values Network or local model call llm_conf × 0.85 (always requires review)

2.2 Unified Confidence Calibration Formula Formula: Wname + Wvalue + Wmethod

Unlike naive string matchers, the final confidence integrates both lexical/semantic match strength and statistical value-profile compatibility:

Multi-Modal Column Confidence Formula
Confidence = Wname × Sname + Wvalue × Vprofile + Wmethod × Amethod
Weight Distribution:
• Wname = 0.45: Lexical/Semantic name similarity score.
• Wvalue = 0.35: Value Profile Fit (VPF) score (0.0 … 1.0).
• Wmethod = 0.20: Method agreement factor (1.0 for memory, exact, or a target found by both fuzzy and semantic; 0.7 for a target found by only one of them, and for LLM).
• Memory Multiplier: If retrieved from approved memory: Confidence ← min(0.99, Confidence × 1.10).
• Empty columns: Vprofile counts as a neutral 0.5, so a correctly named but empty column ("No. of Bldgs") is not out-ranked by weak matches.
• review_required = Confidence < 0.90 (HIGH_CONFIDENCE_THRESHOLD).
Value-Profile Veto
If the column has data and Vprofile(T) < 0.25 (MIN_PROFILE_FIT), the candidate T is rejected no matter how well the header matches, at every tier including memory and LLM. Real cases: building numbers 1–6 under Bldg. as Building Value, $ amounts under Building as Number of Buildings, longitudes as Country. The reason is kept in the mapping evidence.

2.3 1:1 Target Uniqueness (Confidence-Ordered Assignment) Time: O(C × P) worst | Space: O(C)

Within one sheet, two source columns may not populate the same target. Assigning targets left to right lets a weak early match block a strong later one: in SOV_K4T9.xlsx, Account Name ("Client A") took Reference and the exact synonym Location ID was left unmapped. Assignment is therefore ordered by confidence (a greedy approximation, not the Hungarian algorithm).

Assignment Algorithm
  1. Pass 1: score every named column independently (no LLM).
  2. Pass 2: repeatedly take the pending column with the highest current confidence. If its target is already claimed by a column from an overlapping sheet, re-score it with that target excluded and return it to the queue at its new confidence; otherwise commit it. A column still unresolved at its turn gets the LLM tier.
  3. Targets are unique per sheet: columns from different merged sheets (never on the same row) may share a target, e.g. 2023 Building Value and Building Value; Agent 4 coalesces them.
  4. A final safety pass demotes any remaining same-sheet duplicate to UNRESOLVED with the reason in its rationale.
P = number of re-scorings (bounded by C × 17).

Deep Dive Value Profile Fit (VPF) Scoring Matrix

To prevent absurd false positives (e.g., mapping a column named "Bldg." that holds building numbers 1–6 to Building Value), the profiler analyzes actual cell values against each target's expected profile. Ratios are fractions of the column's non-empty values. Exact formulas from score_value_profile_fit (result capped to 0–1):

Canonical Field Primary Value Indicators Score Formulation Logic
Building Value, Contents, BI, Other Numeric values, magnitude ≥ 100 ("monetary") 0.6 × monetary_ratio + 0.4 × numeric_ratio, halved if any value is negative.
Year Built 4-digit years between 1700 and current year + 1 year_ratio, plus 0.3 if >80% numeric and min/max are within range.
Zip 5-digit codes, ZIP+4; 3–4 digit integers (leading zeros lost in Excel) z = max(zip5_ratio, 0.6 × short_zip_ratio); score z if z > 0.5, else z × (1 − min(0.5, monetary_ratio)).
State US state / territory codes; dots and spaces ignored (V.I. → VI) state_ratio.
Fire Sprinklers (Y/N) Y, N, YES, NO, Y13, Y(13R), TRUE, FALSE, 1, 0, SPRINKLERED… min(1, sprinkler_ratio + 0.3 × yn_ratio).
Storeys, Number of Buildings Integers 1 to 200 storey_ratio, plus 0.2 if >80% numeric.
Reference Any identifier; repeats allowed (several buildings per location) 0.2 if >80% numeric with fractions (coordinates, amounts); otherwise 0.5 + 0.5 × unique_ratio.
Address Digits followed by words, or street keywords (St, Ave, Blvd, Rd…) address_ratio, at least 0.3 for text columns (<20% numeric).
City, County, Country Text 0 if >80% numeric; otherwise 0.7 × (1 − numeric_ratio) + 0.3 × (1 − monetary_ratio).
Occupancy, Construction Text or numeric class codes 0.7 × (1 − numeric_ratio) + 0.3 × (1 − monetary_ratio).

Agent 3 Data Quality Rules & Composite Index

3.1 Deterministic Anomaly Detection Time: O(R × F) | Space: O(F)

Agent 3 evaluates 12 deterministic data quality checks over the mapped dataset:

1. Completeness Checks:

Computes null percentage for each target field. Triggers HIGH severity if null rate >50%, MEDIUM if >20%, LOW if >5%.

2. Monetary Validations:

Detects unparsed currency signs ($, ,) → suggests strip_currency. Detects negative monetary exposures, including accounting (1,000) → flags HIGH risk. Detects non-numeric text such as TBD or Included in Bldg → flags MEDIUM for review.

3. Temporal & Physical Limits:

Year Built outside [1700, Current Year] or not a year → suggests to_year_int. Storey counts < 1 or non-numeric, Building counts < 1 → flags logical error. Non-integer values in integer fields → suggests to_int (fractions are kept, never truncated).

4. Standard Codes & Geographic Integrity:

Non-standard sprinkler codes → suggests normalize_sprinkler_code. Full or dotted state names (V.I.) → suggests state_to_abbrev. ZIPs that are not 5 digits → suggests to_zip. Duplicate references → flags HIGH. Missing values (>5% / 20% / 50%) → flags LOW / MEDIUM / HIGH.

3.2 The SOV Data Quality Index Formula Range: 0.0 – 100.0

The system outputs one score summarizing the integrity of the submission. Agent 3 stores it in the quality report and the UI shows the same number (compute_sov_quality_score):

Aggregated Quality Score Formula
QualityScore = 100 × [ 0.35 × Qmapping + 0.30 × Qcompleteness + 0.35 × Qanomalies ]
Component Breakdown:
• Qmapping = (|mapped| / 17) × mean Confidence(mapped): coverage times average mapping confidence.
• Qcompleteness = (∑f ∈ 17 fields NonNullPct(f) / 100) / 17: unmapped fields count as 0.
• Qanomalies = max(0.0, 1.0 - ∑i ∈ issues w(i)): Penalty reduction where:
  – w(High) = 0.20 per critical anomaly (e.g. duplicate IDs, negative values)
  – w(Medium) = 0.08 per format/code issue (e.g. unstripped currency)
  – w(Low) = 0.02 per minor type mismatch
Real-Time Mapping Accuracy KPI Formula
MappingAccuracy = 100 × [ Napproved_predicted / Ntotal_predicted ]
KPI Parameters:
• Ntotal_predicted: Total column mapping recommendations generated by Agent 2 & 3.
• Napproved_predicted: Count of predicted column mappings approved by the underwriter.
• Displayed in the Review tab action bar; updates dynamically as underwriters approve, 1-click reject (dropped from output), or re-assign targets (persisted to ChromaDB as method="human_feedback").

Agent 4 Controlled Transformation Sandbox

4.1 The Zero-Hallucination Mutex Execution Engine Time: O(R × A) | Space: O(R × C)

Agent 4 executes only after human approval. To eliminate generative hallucinations, transformations operate within a sandboxed functional registry: 

# The Transformation Sandbox Execution Pipeline (simplified from _apply_approved_transformations)
def apply_approved_transformations(df, approved_recs):
    # 1. Renames: approved COLUMN_MAPPING recs, highest confidence first,
    #    one claim per target per sheet; columns from different sheets coalesced
    df = rename_and_coalesce(df, approved_pairs)

    # 2. Whitelisted operations on approved STANDARDISATION / DATA_CORRECTION recs
    for rec in approved_recs:
        if rec.operation not in WHITELISTED_OPERATIONS:
            logger.error("Operation %s not in whitelist - REFUSING to apply", rec.operation)
            continue                                  # skipped, never executed
        if rec.operation == "flag_for_review":
            continue                                  # identity: nothing to change

        before = df[rec.target_column].astype(object)
        after = apply_transformation_to_series(rec.operation, before).astype(object)

        # Audit FIRST: count changed rows and sample the first changed row,
        # then write back, so no change can exist without its audit entry
        changed = [not same(a, b) for a, b in zip(after, before)]
        audit_entries.append(create_audit_entry(rec, rows_changed=sum(changed), ...))
        df[rec.target_column] = after

4.2 DataFrame Disambiguation & Collision Resolution Time: O(Cdup × R) | Space: O(1)

Real-world SOVs often have duplicated column headers (e.g., 3 separate columns all labeled 2024 - Increase 10%). Slicing df[col] yields a multi-column DataFrame rather than a Series, crashing subsequent operations.

Collision Resolution Algorithm
1. Header Deduplication: During extraction, if header H appears k times the copies are named H, H (1), H (2), …
2. Series Slicing Disambiguation: If isinstance(df[col], pd.DataFrame) occurs at runtime, the agent evaluates notna().sum() across all candidate column slices and retains the slice with the most non-null values.
3. Stray Target Names: Any source column whose name equals a target field but whose own mapping was not approved (rejected, unreviewed or unmapped, e.g. a raw State column) is renamed to _unmapped_{name} before renaming, so it can never reach the output.
4. Per-Sheet Coalescing: When columns from different merged sheets map to one target, rename_and_coalesce combines them into a single column (rows never overlap; the higher-confidence source wins if they ever do).

Agent 4 Validation & Export Step

5.1 Pandera Contract Enforcement Time: O(R × 17) | Space: O(1)

Before the files are written, the DataFrame is validated against the 17-column specification and the field types:

  1. Cardinality Check: len(df.columns) == 17 (Strict equality).
  2. Ordered Key Alignment: Columns must strictly equal:
    ["Reference", "Address", "City", "State", "Zip", "County", "Country", "Building Value", "Contents", "BI", "Occupancy", "Construction", "Storeys", "Number of Buildings", "Year Built", "Fire Sprinklers (Y/N)", "Other"].
  3. Null Padding: Any unmapped canonical column is initialized as an empty series with dtype object (represented as clean Excel blanks).
  4. Pruning: Excess raw columns not approved for inclusion are safely dropped.
  5. Pandera Lazy Validation: DataFrameSchema(columns={col: Column(nullable=True, required=True)}, strict=True, ordered=True).validate(df, lazy=True).
  6. Type Conformance: every non-null value of Building Value, Contents, BI and Other must be numeric; of Zip, Storeys, Number of Buildings and Year Built, integral. Each failure is reported, e.g. Storeys: 1 non-integer value(s), e.g. 1.5.
  7. Merged-cell check: the written workbook is re-opened; any merged range is a validation error.
  8. Serialization: Cleaned_SOV.xlsx (plus a timestamped copy) is written even when validation fails (stage VALIDATING) so the reviewer can inspect the problems; numeric Zip cells get Excel format 00000 (802 displays as 00802).
