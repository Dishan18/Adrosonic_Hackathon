1. Technology Stack & Design Principles

The system is built on a hybrid deterministic/agentic philosophy: AI and heuristics suggest and map, but strictly whitelisted Python/Pandas functions execute changes with 100% human auditability.

LLM Gateway Groq (Llama-3.3-70b-versatile) + Gemini Fallback 0.37.1 Sub-second data quality reasoning, edge-case anomaly detection, and rationale generation with automated multi-model cascade.

2. System Architecture

The system follows an asynchronous, pipeline-driven architecture divided into five modular layers:

Layer 1: Ingestion
Workbook Processing
OpenPyXL parses multi-sheet Excel/CSV workbooks, unmerges merged title cells, and detects tabular boundaries.
Layer 2: Intelligence
Multi-Agent Cascade
Discovery, 4-stage Schema Mapping, and Quality Reasoning agents generate confidence-scored proposals.
Layer 3: Human Gate
HITL Approval Barrier
Streamlit review console forces underwriting validation for low-confidence or critical mapping decisions.
Layer 4: Execution
Controlled Transformation
Deterministic transformation whitelist runs approved mutations and logs every cell change to an audit trail.
Layer 5: Deliverables
Pandera & Export
Output verified against exact 17-column schema and exported as Cleaned_SOV.xlsx and Audit_Log.xlsx.
Core Architectural Invariant: The LLM is never permitted to directly alter raw tabular cell data. All data mutations are performed by audited, pure Python functions strictly tied to an approved recommendation ID.

3. The 4-Agent Pipeline in Detail

Agent 1: Sheet Discovery & Header Detection (sheet_discovery.py)

Commercial SOVs frequently arrive with preamble metadata, cover letters, legal disclaimers, or multi-sheet workbooks. This agent scans all sheets and locates the true tabular header row.

  • Multi-Factor Sheet Scoring: Evaluates sheet name relevance, row/col density, keyword overlap against insurance terms (e.g. Building, Occupancy, TIV, Address), and string/numeric ratios.
  • Header Row Search: Scans rows 0 through 15 calculating header density, string-to-number ratio, and non-empty column span to isolate the exact header row while skipping decorative titles.
  • Classification: Categorizes sheets into PRIMARY, SECONDARY, or EXCLUDED.

Agent 2: Cascading Schema Mapping (schema_mapping.py)

Maps arbitrary source column headers to the 17 standardized canonical fields using a rigorous 4-stage cascade:

Stage 1: Memory
ChromaDB Recall
Exact match on past human-approved mappings. (Confidence = 1.0)
Stage 2: Exact Match
Lexical Matching
Normalized string comparison against field names and curated aliases. (Confidence = 1.0)
Stage 3: Fuzzy Match
RapidFuzz Token Set
Levenshtein similarity ratio $\ge 0.82$ against target aliases. (Confidence = 0.82 - 0.95)
Stage 4: Semantic
BGE Small Embeddings
Dense cosine similarity between source column name + sample values and target field semantics. (Confidence = 0.70 - 0.90)

Constraint Enforcement: A greedy 1-to-1 matching algorithm guarantees that no two input columns are assigned to the same target field.

Agent 3: Data Quality Reasoning & HITL Generation (quality_reasoning.py)

Performs statistical profiling, anomaly detection, and human review recommendation synthesis.

  • Heuristic Profiling: Detects currency formatting ($ symbols, commas), state spellings, non-integer years, invalid sprinkler codes, and empty values.
  • Quality Scoring: Computes a standardized dataset score (0 to 100) factoring completeness, schema compliance, validity, and consistency.
  • Automated LLM Synthesis: Leverages the Groq LLM Gateway to generate structured, human-readable underwriting explanations ("Why this change is needed", "Impact on portfolio modeling").
  • HITL Review Requirement: If confidence is < 90% or if the operation involves field renaming or schema ambiguity, review_required=True locks the transformation gate until confirmed.

Agent 4: Controlled Transformation & Pandera Validation (transformation.py)

Executes approved recommendations with mathematical determinism.

  • Whitelisted Mutations: Strictly limited to safe operations: strip_currency, to_float, to_int, to_year_int, normalize_state, normalize_sprinkler_code, column_rename.
  • Null Preservation: Missing/blank values are strictly preserved as NaN or empty strings—the system never synthesizes fake property values.
  • Schema Contract: Ensures output has exactly the 17 target columns in the canonical order.
  • Pandera Enforcement: Runs runtime DataFrame validation verifying column types and constraints.
  • Audit Logging: Logs every cell transformation into an immutable, downloadable audit trail.

4. Target Schema — The 17 Canonical Fields

Every submitted SOV, regardless of whether it contains 8 columns or 40 columns, is transformed and structured into the 17 standardized commercial property underwriting fields:

# Canonical Field Name Pandera Type Required Underwriting Purpose Transformation & Validation Rules
1 Reference String Optional Location / Schedule ID Unique location identifier or policy schedule index. Whitespace trimmed.
2 Address String Required Physical Property Address Street address for geocoding and catastrophe accumulation modeling.
3 City String Required Municipality City name for territorial zoning and municipal flood determination.
4 State String Required US State Jurisdiction Standardized 2-letter uppercase postal abbreviation (e.g. CA, NY).
5 Zip String Required Postal Code 5-digit or 9-digit postal ZIP code for CRESTA / postal hazard zoning.
6 County String Optional Administrative District County jurisdiction for wind/hail tiering and local tax assessment.
7 Country String Optional Sovereignty Country code or name (defaults to USA when domestic).
8 Building Value Float64 Required Physical Structure Exposure Replacement Cost Value (RCV) of building. Stripped of currency ($) and commas. $\ge 0$.
9 Contents Float64 Optional Business Personal Property (BPP) Value of equipment, furniture, and inventory. Stripped of formatting. $\ge 0$.
10 BI Float64 Optional Business Interruption / Time Element 12-month gross earnings or extra expense coverage. Stripped of currency. $\ge 0$.
11 Other Float64 Optional Ancillary Structures / Land Fences, signs, paving, and auxiliary outbuildings. Stripped of currency. $\ge 0$.
12 TIV Float64 Required Total Insurable Value Total exposure: Building + Contents + BI + Other. Verified for additive consistency.
13 Occupancy String Optional Operations / Occupancy Type Commercial usage category (e.g. Office, Retail, Manufacturing, Warehouse).
14 Construction String Optional ISO Construction Class Frame, Joisted Masonry, Non-Combustible, Fire Resistive, or ISO class (1-6).
15 Storeys Int64 / Float Optional Building Height / Floors Number of above-ground floors for fire rescue and seismic vulnerability.
16 Number of Buildings Int64 / Float Optional Complex Structure Count Total distinct physical structures situated on the designated parcel.
17 Year Built Int64 / Float Optional Construction Year 4-digit integer year (e.g. 1998). Must fall between 1700 and current year.

7. Putting Into Production & Scaling Strategies

To scale this system from hackathon demo to an enterprise-grade commercial underwriting platform processing tens of thousands of complex property schedules monthly, implement the following architectural enhancements:

A. Microservices Decoupling (API & Worker Separation)

  • FastAPI Core Service: Replace direct Streamlit processing with a high-throughput async FastAPI gateway exposing /api/v1/sov/upload, /api/v1/sov/{id}/status, /api/v1/sov/{id}/approve, and /api/v1/sov/{id}/export.
  • Celery + Redis Task Workers: Offload heavy workbook parsing, embedding generation, and Pandera validations to distributed Celery workers running on containerized worker nodes (AWS ECS / Kubernetes).
  • WebSocket Real-Time Progress: Stream pipeline stage updates (Discovery → Mapping → Quality) to the frontend via WebSockets instead of blocking HTTP requests.

B. Distributed Vector Store & Relational State Management

  • PostgreSQL + pgvector: Replace local embedded ChromaDB with managed PostgreSQL using the pgvector extension. Store both relational session state (audits, recommendations, user approvals) and 384-d semantic column embeddings in a single ACID-compliant database.
  • Tenant Isolation: Partition episodic mapping memory by broker_id or carrier_id so firm-specific synonyms (e.g. Aon vs. Marsh naming conventions) are recalled accurately without cross-tenant bleed.

C. High-Performance Caching & Cost Optimization

  • Exact Header Redis Cache: Cache MD5 hashes of row-0 headers. If an identical broker spreadsheet layout is processed again, retrieve 100% of mappings in < 5ms with zero LLM API or embedding costs.
  • Selective LLM Invocation: Retain the current design where 90%+ of mappings are solved deterministically via Memory, RapidFuzz, and Cosine similarity. Only route unresolved anomalies or edge-case occupancy reclassification to the LLM Gateway.

D. Enterprise Security, Auditing & Compliance

  • S3 / Azure Blob Storage with KMS Encryption: Store uploaded raw files and finalized Cleaned_SOV.xlsx files in private object stores encrypted at rest via AWS KMS (AES-256).
  • Immutable Tamper-Evident Audit Trails: Export audit log entries with SHA-256 hash chains to satisfy internal model governance and external insurance regulator examinations (NAIC / Lloyd's compliance).
  • PII Redaction: Strip individual property owner names or contact phone numbers prior to any third-party LLM inference.
